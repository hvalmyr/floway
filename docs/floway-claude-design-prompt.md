# Промпт для Claude Code: фронтенд сайта школы «ФлоВей»

Скопируйте текст ниже целиком и передайте его Claude Code в терминале проекта (или как первое сообщение в новой сессии).

Этот документ — готовый промпт. Всё, что ниже разделителя «— НАЧАЛО ПРОМПТА —», нужно скопировать одним куском.

— НАЧАЛО ПРОМПТА —

Разработай фронтенд сайта школы флористики «ФлоВей» на основе дизайн\-системы ниже. Это лендинг из 4 типов страниц: главная, страница курса, страница/листинг мастер\-классов, контакты. Сайт на русском языке, ЦА — женщины 25–45, тон дружелюбный и "ручной".

## Стек

Nuxt 3 (Vue 3, Composition API, `<script setup>`) \+ TypeScript \+ Tailwind CSS. Рендеринг — SSR/SSG через Nuxt (`nuxt generate` или гибридный режим), это лендинг, SEO важен. Формы — `vee-validate` \+ `zod` (через `@vee-validate/zod`). Анимации — встроенные Vue `<Transition>`/`<TransitionGroup>` для аккордеона и микро\-интеракций, без лишних библиотек.

Бэкенд — отдельный сервис на Go, фронтенд обращается к нему по REST/JSON. В Nuxt держим единый слой доступа к API — `composables/useApi.ts` (обёртка над `$fetch`/`ofetch` с базовым URL из `runtimeConfig.public.apiBase`), никаких прямых `fetch()` внутри компонентов.

Структура проекта: `pages/` (страницы, файловый роутинг Nuxt), `components/ui/` (кнопки, карточки, теги, поля — переиспользуемые примитивы), `components/sections/` (блоки страниц: `Hero.vue`, `Features.vue`, `CourseCard.vue` и т.д.), `composables/` (доступ к API, формы, медиа\-запросы), `content/` или `server/` при необходимости заглушек, `assets/styles/tokens.css` (CSS\-переменные), `types/` (общие TS\-типы, в идеале сгенерированные/синхронизированные со схемой Go API).

## Дизайн\-токены (вставить как есть)

Расширь `tailwind.config.ts` темой и создай `assets/styles/tokens.css`, подключённый в `nuxt.config.ts` (`css: ['~/assets/styles/tokens.css']`), со следующими значениями:

Цвета: `primary-50 #EAF2F7`, `primary-300 #A9C9DD`, `primary-500 #82B1CC`, `primary-600 #5F93B3`, `primary-700 #42708F`, `ink-900 #41342A`, `ink-700 #6B5D51`, `ink-400 #A79A8E`, `surface #F7F5F3`, `surface-100 #FBFAF9`, `line #E4DFDA`, `white #FFFFFF`, `success #5B9A6F`, `error #C15B4A`.

Шрифты: заголовки — `Nunito` (веса 700/800/900, кириллица), основной текст — `Onest` (веса 400/500/600, кириллица). Подключи через модуль `@nuxtjs/google-fonts` (или `@nuxt/fonts`) с `subsets: ['cyrillic']`, не через ручной `<link>`. Заголовки через `clamp()`\: H1 `clamp(2.25rem, 1.6rem + 2.6vw, 4rem)`, H2 `clamp(1.75rem, 1.4rem + 1.6vw, 2.75rem)`.

Радиусы: `sm 12px`, `md 20px`, `lg 28px`, `pill 999px`.

Отступы (spacing scale): `4,8,12,16,24,32,40,48,64,80,96,120,160` — используй именно эти значения в классах Tailwind (`p-*, gap-*, my-*`), не произвольные px.

Контейнер: `max-width 1280px`, `padding-inline` — 64px (desktop), 40px (tablet), 24px (mobile), 16px (мелкий mobile).

Брейкпоинты Tailwind: `sm 480px`, `md 768px`, `lg 1024px`, `xl 1280px`.

Установи `@nuxtjs/tailwindcss` как модуль Nuxt (не голый postcss\-конфиг) — это даёт корректный порядок сборки CSS и HMR.

## Обязательные UI\-примитивы (`components/ui/`)

Все примитивы — однофайловые `.vue`\-компоненты (`<script setup lang="ts">`), пропсы типизированы через `defineProps<{...}>()`, без Options API.

`UiButton.vue` — варианты `primary | outline | outline-inverted` через проп `variant`, размеры `md | lg`, pill\-форма, состояния hover/active/focus\-visible/disabled согласно ниже. Primary: фон `primary-600`, текст белый (НЕ `primary-500` — недостаточный контраст, см. раздел «Доступность»). Hover → `primary-700` \+ `translate-y-[-1px]`. Focus\-visible → `outline: 2px solid var(--ink-900); outline-offset: 2px`. Рендерь как `<button>` или `<NuxtLink>` в зависимости от переданного `to` (единый компонент для обоих случаев через `<component :is>`).

`UiCard.vue` — базовая карточка с `radius-md`, паддинг 32px, три цветовых варианта (`surface-white | surface-primary | surface-ink`) для карточек курсов, слоты `#media`, `#title`, `#default`.

`UiBadge.vue` — pill\-тег с обводкой, вариант для лейблов вроде «работаем с 2013 года».

`UiAccordion.vue` / `UiAccordionItem.vue` — для программы курса; используй `<TransitionGroup>` или CSS `grid-template-rows: 0fr → 1fr` вместо JS\-измерения высоты. Иконка `+` поворачивается в `×` (45deg) при раскрытии. Управление раскрытым состоянием — через `provide/inject` или простой `v-model` массива открытых id на родителе, оберни transition в `@media (prefers-reduced-motion: no-preference)`.

`UiInput.vue`, `UiTextarea.vue`, `UiRadioGroup.vue` — поля форм, интегрированные с `vee-validate` (`useField`). Focus\-ring `0 0 0 3px var(--primary-50)` \+ смена обводки на `primary-600`. У `UiRadioGroup` кликабельна вся строка (min\-height 44px). Обязательно: состояние ошибки (`aria-invalid`, текст ошибки `error`, `aria-describedby`).

`UiPhoneInput.vue` — маска `+7 (___) ___ __ __` (например, через `v-mask`\-подобную директиву или ручной обработчик `input`), `inputmode="tel"`.

`SectionHeading.vue` — H2 \+ необязательный лид\-абзац по центру через слот, используется на всех секциях лендинга.

## Страницы и контент

### 1\. Главная (`pages/index.vue`)

Hero: H1 «Mы рядом с первого букета», лид\-абзац «Обучаем современной флористике с нуля — бережно, понятно, с практикой и поддержкой», кнопки Primary «Курсы» \+ Outline «О школе», справа — плейсхолдер под фото/видео (`aspect-[4/3]`, `bg-surface`, скруглённый).

Секция «Почему стоит учиться в школе ФлоВей» — H2 \+ лид, сетка 3 колонки (2 на tablet, 1 на mobile) из 6 фича\-карточек: «два формата обучения», «комфортное обучение», «центр Москвы», «гибкий старт», «максимум практики», «для любого уровня» — у каждой иконка (пакет `lucide-vue-next`), заголовок, короткое описание (текст взять из макета/аналогичный).

Секция «О школе» — H2 \+ 4 раскрывающихся блока (Badge\-заголовок внутри карточки \+ описание): «есть свободный формат», «есть групповой формат», «маленькие группы до 7 человек», «только живые цветы». Плюс верхний блок с бейджем «работаем с 2013 года» и текстом об истории школы.

Секция курса «Основы флористики» — H2 в кавычках, лид\-абзац, 2 карточки курса (`UiCard` variant `surface-primary` и `surface-ink`) — «Блок “Букеты”» (7 занятий, 30 часов) и «Блок “Композиции”» (4 занятия, 16 часов), у каждой медиа\-плейсхолдер и кнопка «узнать больше».

Секция «Профильные курсы» — H2 \+ 3 карточки (`surface-ink`, `surface-primary`, `surface-white` с обводкой) — «Коммерческая флористика», «Актуальная флористика», «Свадебная флористика», с плейсхолдерами под кол\-во занятий/часов (компонент должен принимать `undefined` и рендерить «—», т.к. в макете эти значения ещё не заполнены).

Форма заявки переиспользуемая — см. раздел «Форма заявки» ниже (на главной — блок «Записаться на курс» или ведущая к записи кнопка — реализуй как отдельный переиспользуемый `<ApplyForm />`, встраиваемый на разные страницы).

### 2\. Страница курса (`pages/courses/[slug].vue`)

Hero с H1 «Курс “Основы флористики”», описанием, кнопкой Primary «Оставить заявку», фото справа.

Блок цены: строки с `Блок «Букеты»` / `7 занятий` / `30 часов` / `38 500 ₽`, вторая строка `Блок «Композиции»` / `4 занятия` / `17 часов` / `22 000 ₽` (зачёркнутая старая цена, если есть скидка — добавь опциональное поле `oldPrice`).

«Учебный план» — H2 \+ лид \+ `UiAccordion` со списком занятий (Занятие 1…7), где первый пункт открыт по умолчанию и содержит: «Темы:», «Вы научитесь:», «Продолжительность:». Повторить для второго блока («Композиции»).

В конце страницы — `<ApplyForm />` с заголовком «Записаться на курс».

Данные курса (`title, description, modules[]`) получай с Go\-бэкенда через `useAsyncData('course', () => useApi().getCourse(slug))` внутри `<script setup>` страницы; на время отсутствия API — заглушка\-мок в `mocks/courses.ts` с теми же TS\-типами, чтобы переключение на реальный API не ломало компоненты. Это должно легко расширяться на другие курсы (Коммерческая, Актуальная, Свадебная флористика).

Мастер\-классы: «Круглый букет» (2–3 часа, 3000₽ / 4500₽ с сноской о разнице), «Раскидистый букет» (4 часа, 5500₽), «Круглая композиция» (2–3 часа, 3500₽), «Раскидистая композиция» (3–4 часа, 6000₽), «Интерьерный букет» (3–4 часа, 6000₽), «Интерьерная композиция» (цена/время по аналогии — оставь `TODO` в контент\-файле, в макете обрезано).

Детальная страница мастер\-класса — та же структура, что и в листинге, но как отдельная страница с собственным `<ApplyForm />` внизу. Список мастер\-классов и их slug'и — также через `useApi()`, с `definePageMeta({ validate })` для проверки существования slug и 404 через `showError`.

## Форма заявки (`ApplyForm.vue`)

Поля: имя (текст, required), телефон (`UiPhoneInput`, required), почта (email, опционально), радиогруппа «Как с вами связаться?» (Позвоните мне / Telegram / Whatsapp / Max), радиогруппа «Откуда вы о нас узнали?» (По рекомендации / Реклама / В интернете / В соцсетях / В картах). Кнопка Primary «Отправить заявку» на всю ширину.

Валидация — `vee-validate` \+ `zod`\-схема в `lib/validation/applyForm.ts`. Отправка — через `useApi().submitApplication(payload)` (POST на Go\-эндпоинт, например `POST /api/v1/applications`, см. раздел «Интеграция с Go\-бэкендом»). Показывай состояния загрузки (блокировка кнопки \+ спиннер), успех (токен `success`, замена формы на благодарность) и ошибку сети/сервера (токен `error`, текст ошибки \+ повторная попытка), не просто `console.log`.

## Доступность — обязательно проверить

Контраст текста на кнопках и бейджах (используй `primary-600`/`primary-700`, не `primary-500`, для текста на светлом или белого текста на цветном — см. дизайн\-систему, раздел 2.3). Все интерактивные элементы имеют видимый `:focus-visible`. Иконки — `aria-hidden`, фото — содержательный `alt`. Touch\-таргеты ≥44×44px. Семантическая разметка (`<nav>`, `<main>`, `<footer>`, один `<h1>` на страницу, логичная последовательность заголовков). `prefers-reduced-motion` уважается везде, где есть transition/animation.

## Адаптивность — обязательно проверить на каждой странице

Все сетки: 3 → 2 → 1 колонка на `lg → md → sm`. Hero: 2 колонки → стек (текст, затем CTA, затем медиа) ниже `lg`. Кнопки — на `sm` растягиваются на всю ширину контейнера. Инфо\-плашки цены — на mobile переходят с горизонтального ряда на вертикальный стек значений. Изображения — компонент `<NuxtImg>` из `@nuxt/image` с `format="webp"`, явными `sizes` под брейкпоинты и `fit="cover"`, никаких сжатий/растяжений исходного аспекта.

## Интеграция с Go\-бэкендом

Фронтенд не знает деталей реализации Go\-сервиса, поэтому всю работу с API вынеси в один слой:

`composables/useApi.ts` — обёртка над `$fetch` (`ofetch`) с `baseURL` из `useRuntimeConfig().public.apiBase` (задаётся через `NUXT_PUBLIC_API_BASE` в `.env`), методы: `getCourses()`, `getCourse(slug)`, `getMasterClasses()`, `getMasterClass(slug)`, `submitApplication(payload)`. Ошибки сети/5xx обрабатываются в одном месте (нормализованный тип `ApiError`), а не разбросаны по компонентам.

Типы данных (`types/api.ts`) описывай по структуре, которую ожидаешь от Go\-JSON (`snake_case` в ответе, если бэкенд использует стандартные `encoding/json`\-теги — уточни у бэкенд\-разработчика, не угадывай). Если контракт ещё не согласован с бэкенд\-командой — оставь `// TODO: согласовать формат ответа API` возле типов, не выдумывай поля.

На время, пока API не готов — все `get*`\-методы возвращают данные из `mocks/*.ts` через флаг в `runtimeConfig` (`useMocks`), чтобы верстка и интеграция с бэкендом шли параллельно.

CORS и прокси в dev\-режиме — настрой `nitro.devProxy` в `nuxt.config.ts`, чтобы запросы с `localhost` шли на Go\-сервер без ручной настройки CORS на каждом разработчике.

## Что нужно сдать

Рабочий Nuxt\-проект, который собирается (`npm run build` / `nuxi build`) без ошибок и без предупреждений ESLint/TypeScript (`vue-tsc --noEmit` чистый). Каждый компонент из `components/ui/` должен иметь пример использования в JSDoc/комментарии сверху файла. Lighthouse (mobile) по доступности ≥ 95. Все 4 типа страниц адаптивны от 360px до 1920px без горизонтального скролла и наложения элементов.

Если что\-то в контенте помечено выше как `TODO` (незаполненные цены/часы, карта, формат ответа API) — оставь явный `// TODO:` комментарий в коде с описанием, что нужно уточнить у заказчика/бэкенд\-команды, а не выдумывай данные.
